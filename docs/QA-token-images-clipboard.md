# Изображения фишек и буфер обмена

Ветка: `feature/local-token-images`, поверх `feature/local-map-backgrounds` / f950993.
Реализовано в коде, новая ручная приёмка и выпуск не подтверждены.

## Поведение и ограничения

- При создании фишки доступны прежний URL, PNG/JPEG с устройства и изображение из буфера. Для существующей фишки — кнопка изменения изображения, затем сохранить/отмена. Отмена не меняет фишку.
- Для создания карты и замены фона доступны те же способы. Кнопка буфера читает его только после нажатия; Ctrl+V обрабатывается только в отдельном поле. В редакторе поста обычная вставка текста/BBCode сохраняется.
- Clipboard API требует поддержки браузера и безопасного контекста (HTTPS или localhost); при отказе разрешения показана подсказка Ctrl+V/выбор файла. HTTP по сетевому IP может запрещать кнопку. Файл передаётся на сервер только штатным действием создания/сохранения; для замены фона выбор сразу запускает существующее действие замены.
- Вход PNG/JPEG: до 10 МиБ, 8192 px по стороне, 16 × 1024² пикселей и доступной памяти PHP. Расширение/MIME от клиента не считаются доказательством формата; SVG/GIF/APNG и повреждённые данные отклоняются. Изображение декодируется и перекодируется; JPEG metadata удаляются.
- Фишка пропорционально уменьшается до 512 × 512, без увеличения маленьких изображений; круглая обрезка остаётся отображением. Фон не уменьшается до 512.
- Файлы фишек: `storage/interactive-maps/tokens/{id}`; фоны: `storage/interactive-maps/backgrounds/{id}`. Нужен постоянный том и резервная копия вместе с БД. Старые файлы после замены/удаления не очищаются автоматически; квот пока нет.
- Создание/замена — только manage permission. Чтение — управляющий или авторизованный читатель видимого поста с этой картой, включая visibility scopes сторонних расширений. Гость получает 403, недоступная карта/старый URL — 404. URL с непрозрачным ключом без расширения проходит штатный PHP web-server; private/no-store и nosniff. Произвольный внешний URL сохраняет свою внешнюю политику доступа.
- Замена сохраняет координаты, владельца и moveVersion. Ответ изменения картинки не должен откатывать параллельное движение/переназначение. Новое изображение входит в следующий token snapshot; фон по-прежнему требует явного обновления другим клиентом.
- Ошибка записи БД/хранилища сохраняет прежнее изображение и удаляет только новый неподтверждённый файл; bounded transaction retry не оставляет дубликат. При неизвестном исходе commit файл сохраняется, чтобы не повредить потенциально сохранённую ссылку.

## Проверить владельцу после согласованного обновления

1. Создать карту и фишку через устройство; проверить пропорции, прозрачность PNG и вид круга.
2. Скопировать реальное изображение в буфер, создать карту/фишку кнопкой или Ctrl+V в специальном поле. Проверить отказ кнопки в своём браузере и доступность резервного способа.
3. Заменить изображение существующей фишки, затем проверить отмену и ошибочный файл; имя, координаты и владелец сохраняются. Старое неподтверждённое перемещение не должно повторяться.
4. Два клиента: движение/переназначение, новая картинка в снимке, отказ прежнему владельцу и отсутствие управления загрузками у игрока. Гость/скрытая тема не получают закрытый файл.
5. Обычная тема, ответ, вставка текста/BBCode, picker/отмена и отображение над/под текстом/сворачивание проходят без регрессий.

Новых upload-миграций нет. Cumulative build содержит отдельную миграцию двух полей прикрепления; применять на стенде только после свежей резервной копии и отдельного разрешения. [Порядок обновления](UPGRADE-embed-upload.md).
