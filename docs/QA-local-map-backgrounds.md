# QA: фон карты с устройства

Ветка feature/local-map-backgrounds основана на отдельных presentation и
generic-placeholder изменениях. Это тестовая сборка, выпуск не разрешён.

## Возможности и ограничения

Создание карты принимает прежний JSON:API с backgroundUrl либо multipart
title + image. В редакторе POST /chak-maps/{id}/background заменяет только фон.
Создание/загрузка требуют map.manage и штатного CSRF. При ошибке форма сохраняет
название и выбранный файл для явного повтора. URL-вариант остаётся доступен.

Поддержаны статичные PNG/JPEG: до 10 МиБ исходного и обработанного файла,
8192 px по стороне и 16 × 1024² пикселей. Реальное содержимое проверяется,
декодируется и перекодируется; клиентские имя/MIME не определяют тип хранения.
JPEG EXIF удаляется. SVG/GIF/WebP/APNG в этом шаге не поддержаны. APNG и слишком
большие размеры отклоняются до декодирования; используется консервативная
проверка доступной памяти PHP. PHP/web-server могут ограничить загрузку сильнее.
Ошибки upload_max_filesize/post_max_size обрабатываются как отказ загрузки;
настройки сервера расширение самостоятельно не меняет.

Используется существующая библиотека Flarum Intervention Image; явно объявлен
минимум ^3.11, нужный для JPEG strip API (в 3.2 его нет). Новых пакетов, внешнего
хранилища или платных сервисов не добавлено.

## Хранение и права

Файлы: storage/interactive-maps/backgrounds/{mapId}/{random128bit}.png|jpg,
вне public. GET /chak-maps/{id}/background/{opaque32hexkey} требует текущую карту/URL
и map.manage либо хотя бы одно разрешённое видимое comment-прикрепление карты.
Применяются зарегистрированные post/discussion visibility scopes. Гость —403,
недоступный viewer —404, без изображения; success/error private,no-store,
успешный ответ nosniff и фиксированный image Content-Type. Случайное имя не
заменяет авторизацию. URI не имеет расширения, чтобы стандартный сервер не перехватывал его как статический PNG/JPEG до Flarum. Открепление последней доступной связи отзывает чтение.

Map+file создаются атомарно с компенсацией записи файла при отказе DB.
При замене старый URL сохраняется при ошибке; удаляется только новый файл
неуспешного запроса. При успешной замене старые файлы остаются на диске, но
старый URL перестаёт отдавать изображение. Автоматическая очистка/квота пока
не реализованы; учитывать дисковое место. Карты, фишки, связи и пользовательские
данные при загрузке не удаляются. Сетка/координаты сохраняются. Другим открытым
клиентам для нового фона по-прежнему нужна кнопка обновления карты.

## Проверки

PHP fixtures используют только in-memory/temp либо именованный локальный
синтетический форум: PNG/JPEG, неверный MIME/имя, polyglot normalization,
пустой/повреждённый/oversize stream, APNG, dimensions/memory; реальные
hidden/private/custom-scoper image denials; исключения при сохранении create
и replace и отказ storage, без оставшейся карты/нового файла. Все DB записи
откатываются. Проверки row counts запускать отдельно от browser writers.

Browser: file/URL выбор и отмена файла; создание PNG; замена JPEG с сохранением
grid/tokens; fake PNG rejection и retry; guest/player upload denial;
protected image до/после attach/hide/restore/detach; ошибка сети сохраняет draft;
старый GET редактора не заменяет новый фон. Все прежние 27 cases сохраняются;
точные результаты общего 31-case набора и CI записываются в PROJECT-CONTEXT.

## Подготовка обновления стенда

Загрузка файлов не требует новой таблицы/колонки. В совокупной сборке есть
миграция presentation: chak_map_embeds.display_position VARCHAR(5) default
'below' и starts_collapsed boolean default false. Перед её применением нужны
отдельное разрешение владельца и свежая копия БД. Только точечный helper
scripts/Migrate-EmbedPresentation.php; никаких общих migrate/reset/down -v.

Сохранить исходники/generated assets, SQL и storage/interactive-maps
(лучше весь storage). Файлы находятся вне extension, Git/extension.tgz их
не сохраняют. После загрузки они должны находиться на постоянном томе Flarum.
В PowerShell 5.1 не направлять бинарный tar через `>`: создать архив внутри
контейнера, скопировать docker cp и проверить tar -tzf. SQL не публиковать.
Конкретные команды upgrade выдаются только после финального CI и согласования
миграции; текущая e917eaa остаётся принятой базой до явного обновления.

карте и сохранение фишек/сетки; отказ неверного/большого файла и повтор;
права гостя/игрока и доступ к фону через пост. Повторить presentation cases
above/below, initial collapse, независимость зрителей и возврат сети/вкладки.
Нужна проверка реальных PHP/прокси-лимитов и постоянного хранения на стенде.
Код, автоматические результаты, ручная приёмка и решение о релизе — отдельные
статусы. Новая сборка ещё не принята владельцем/к выпуску.
