# Расположение и сворачивание карты — предложение

Запрос владельца от 2026-10-27. Статус: проектирование, код ещё не реализован.
Текущая проверяемая сборка e917eaa не меняется. Владелец уточнил:
«карта в теме» означает карту в первом сообщении темы.

## Предлагаемое поведение

В окне прикрепления и при выборе карты в composer дать два параметра:

- Расположение: «Над текстом» / «Под текстом».
- Начальное состояние: «Развёрнута» / «Свёрнута».

Они относятся к конкретному прикреплению. Одна карта может быть сверху
в первом посте и снизу в другом, с независимым начальным состоянием.
Для существующих прикреплений сохранять «Под текстом, развёрнута».
Изменение этих параметров требует тех же manage + embed + edit прав,
что прикрепление; обычные ограничения Flarum на старые/чужие посты сохраняются.
Текст сообщения и инертный BBCode-маркер не используются для хранения настроек.

Для всех разрешённых зрителей доступна компактная кнопка
«Показать карту» / «Свернуть карту». Переключение влияет только на просмотр
этого прикрепления данным клиентом, не меняет общий default и не делает
запись в БД. Начальный default выбирает авторизованный прикрепляющий.
Запоминание личного выбора между посещениями не входит в первый шаг.

Свёрнутый блок занимает одну строку с кнопкой. Кнопка работает с клавиатуры,
несёт aria-expanded/aria-controls. Спойлер не ограничивает серверные права
и не создаёт нового вида скрытых/секретных карт.

## Быстродействие и синхронизация

- Изначально свёрнутая карта не загружает фон/фишки до раскрытия.
- Свёрнутое прикрепление не участвует в периодическом опросе; другие видимые
  прикрепления той же карты продолжают обновляться независимо.
- При раскрытии проверить актуальную доступность и получить свежие данные
  до разрешения drag; не показывать устаревший кеш после отзыва доступа.
- Сворачивание во время незавершённого drag отменяет только неподтверждённый
  жест. Уже отправленная запись завершается обычным протоколом очереди;
  нельзя сообщать, что она отменена, если сервер мог её принять.
- Поздние ответы не раскрывают блок сами и не обходят existing epoch/busy
  guards. 403/404/409/428 и явный повтор хода сохраняют прежний смысл.

## Встраивание и данные

Сейчас index.js добавляет EmbeddedPostMap в конец CommentPost.content().
При реализации размещать карту до/после текстового тела комментария,
сохраняя штатные служебные блоки Flarum и единообразный unkeyed vnode list.
Простой unshift в общий content-массив без проверки его структуры недостаточен:
он может поставить карту выше служебных элементов поста.

Общие настройки следует хранить в chak_map_embeds, а не chak_maps: положение
и default раскрытия относятся к связи карты с сообщением. Предлагаемые
additive поля: display_position (above/below) и starts_collapsed (boolean).
Точные SQL-типы/миграция будут подготовлены при реализации; перед применением
к существующей БД обязательны свежая резервная копия и отдельное разрешение
владельца. Сейчас миграция не создаётся и не применяется.

Передать минимальные параметры прикрепления в post resource без N+1,
с теми же privacy правилами. Для закрытого блока безопаснее общий заголовок
«Игровая карта», пока доступ и данные не проверены. Старые клиенты должны
получать безопасные default значения при отсутствии новых атрибутов.

## Карта в первом сообщении темы

Владелец подтвердил этот вариант: используется обычное прикрепление к первому
сообщению, с теми же настройками и правами. Положение сверху/снизу задаётся
относительно текста первого сообщения. Существующая post association подходит
для этого сценария; дополнительных сущностей темы не требуется.

## Проверки перед приёмкой

1. Над/под текстом при новой теме, ответе и сохранённом редактируемом посте;
   BBCode, меню, заголовки и остальные штатные элементы Flarum сохранены.
2. Старые прикрепления остаются снизу и развёрнутыми после upgrade.
3. Сворачивание мышью/клавиатурой, несколько независимых прикреплений,
   мобильная ширина и тема владельца.
4. Изначально свёрнутая карта не загружает изображения/фишки и не опрашивается;
   раскрытие загружает свежую позицию, включая перемещение другим клиентом.
5. Отзыв доступа, скрытие/открепление во время свёрнутого состояния:
   раскрытие не возвращает старую карту или токены.
6. Сворачивание во время drag, pending save и задержанного GET; конфликт,
   повторное раскрытие, ошибка сети и восстановление без дублирующей записи.
7. Права настройки проверяются сервером для admin/GM/игрока/гостя;
   личное раскрытие не изменяет общий default.
