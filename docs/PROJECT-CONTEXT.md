## 1. Цель и принципы продукта

**Interactive Maps** — публичное расширение для **Flarum 2.x** (не кастомизация единственного личного форума) для форумных НРИ и ролевых игр. Репозиторий: [ChakChakman/flarum-interactive-maps](https://github.com/ChakChakman/flarum-interactive-maps). Пакет Composer: `chakchakman/flarum-interactive-maps`, лицензия MIT.

- **Мастер / администрация** создаёт карту, выбирает фон, редактирует сетку, размещает фишки и назначает их конкретным игрокам.
- **Игрок** взаимодействует с картой непосредственно в разрешённом ему сообщении обсуждения, видит чужие фишки, но может перемещать **только свою назначенную фишку**.
- Каталог `/maps` — инструмент персонала, а не отдельное игровое пространство для всех участников.
- Карта — **переиспользуемый объект**: её прикрепление или открепление от поста не должно удалять карту, фишки или текст сообщения.
- Не нарушать обычную работу форума ради расширения: исходный текст постов, создание тем и ответов, BBCode-панель, маршруты Flarum, другие расширения и обычная прокрутка должны продолжать работать.

### Модель доступа и безопасность

- Права `chakchakman-interactive-maps.map.manage` (управление каталогом и картами) и `chakchakman-interactive-maps.map.embed` (привязка карты к **доступному для редактирования** посту) проверяются на **PHP-сервере**, а не только скрытием кнопок.
- Обычный пользователь и гость не должны получать каталог или подробности карты через угадывание ID.
- Встроенная карта доступна только при реальной привязке к конкретному посту и наличии права читать обсуждение. Приватные обсуждения не должны раскрывать фон/фишки через прямой URL/API.
- Перемещение фишек игроками требует аутентификации, проверки владельца фишки, связи карты с постом и права чтения обсуждения. Нельзя открывать всем старый `/api/chak-tokens/{id}/move`.
- Группа «модераторы» не привилегированная по имени. При тестировании Flarum 2 обнаружено, что неподтверждённый email тестового пользователя может препятствовать наследованию прав его назначенной группы; проверять статус подтверждения прежде чем менять код авторизации.

Подробнее: [docs/PRODUCT-VISION.md](PRODUCT-VISION.md).

## 6. Процесс разработки и обновления этого документа

**Источник истины для кода** — коммиты/PR в GitHub; **источник истины для подтверждённой работоспособности** — записанные результаты испытаний в реальном Flarum. Нельзя выдавать автоматический тест за ручную приёмку.

1. **Сразу после появления идеи:** добавить пункт ниже со статусом **Предложено**. Не считать решение утверждённым до явного согласования.
2. **После согласования:** перевести в **Принято**, указать ограничение/мотив и предполагаемый этап.
3. **Перед созданием каждого нового PR:** обновить этот документ в той ветке, из которой создаётся PR, указав исходный рабочий baseline, объём изменений, пользовательскую ценность, риски, план QA и условия отката. Если решение уже отражено без изменений, добавить ссылку на существующее решение вместо дублирования.
4. **В ходе реализации:** отмечать **В работе**, ссылку на PR/коммит и новые обнаруженные ограничения. Синхронизировать UX-спецификации с `docs/PRODUCT-VISION.md` и планы с `ROADMAP.md`.
5. **После тестирования:** разделять **Код готов / CI прошёл / Проверено в Flarum / Принято / Выпущено**. Записывать точный коммит и что проверено/не проверено.
6. **При изменении прежней договорённости:** оставлять запись о смене решения и почему оно поменялось, а не незаметно переписывать историю.
7. **Перед релизом:** права гостя/игрока/GM/администратора, защита API от обхода, создание постов/BBCode, отсутствие ошибок Mithril/500, целостность карт/фишек, собранные JS-файлы, тест чистой установки и план отката.
8. **Историческое правило:** не менять рабочую локальную сборку при незакоммиченных `dist` без её сохранения; не делать опасные операции с БД. Доработки готовить в GitHub, локальный Docker использовать для проверки. Один рабочий форум достаточен на текущем этапе.

### Диагноз и исправления

- Проверены страницы PR, Checks и Actions. Для `1a17c84` Extension CI успешен, но последние runtime-smoke push/PR runs `40035686849` / `40035691801` падают на **Exercise forum UI**. GitHub API из облачной среды возвращает `Forbidden`; публичная страница job требует вход для подробных логов. Причина ниже подтверждена **локальным воспроизведением того же теста**, а не выдана за прочитанный лог CI.
- После отправки ответа Flarum кратковременно показывает предварительный и сохранённый пост с одинаковым текстом. `.Post-body` с фильтром по тексту находит два элемента и вызывает Playwright strict-mode violation. Теперь тест проверяет HTTP 201, получает ID из ответа `POST /api/posts`, находит ровно один сохранённый `.PostStream-item[data-id]` и проверяет его после перезагрузки. Создание тем/ответов не было ошибкой приложения.
